Build a plugin

Author a plugin

A Kora plugin is a JSON file describing how to read a site, or configuration for an integration, tool or theme. There is no code to compile — you write a definition, publish it in a registry, and Kora fetches it at runtime.

#Categories

Set category to one of four values. It decides both how the hub renders the entry and which runtime loads it.

Plugin categories
categoryWhat it needsAppears in
source baseUrl plus endpoints or theme Discover
integration Its own runtime's config, plus a target Workshop
tool Its own runtime's config Workshop
theme A palette; no endpoints needed Settings

Omitting the field

A definition with no category is treated as a source, which is the right default for a plain source definition. If you are writing anything else, set it explicitly.

#Choosing a runtime

Sources run on one of two shared engines. Pick by what the site offers:

Source runtimes
If the site…UseYou write
Runs the WordPress madara plugin "theme": "madara" Usually just baseUrl. Overrides only where the site deviates.
Exposes a JSON API "api": "json" endpoints mapping JSON fields to results.

A large share of the Tachiyomi source list runs on Madara, so one port covers a lot of sites. Check the site's HTML for Madara's characteristic markup before writing selectors by hand — hand-written selectors for a Madara site break when the site updates its theme.

For a Madara source that sits behind a bot wall, add "client": "cloudflare" to route requests through the Worker instead of fetching directly.

#JSON-API source

A complete, working definition, copied from the Project Gutenberg source in the shipped registry: 

{
  "id": "kora-legal-gutenberg",
  "name": "Project Gutenberg",
  "lang": "en",
  "version": 1,
  "nsfw": false,
  "kind": "book",
  "api": "json",
  "piracy": false,
  "baseUrl": "https://gutendex.com",
  "icon": "https://www.gutenberg.org/cache/epub/1342/pg1342.cover.medium.jpg",
  "website": "https://www.gutenberg.org",
  "description": "Project Gutenberg — over 75,000 public-domain eBooks, read via the Gutendex catalogue.",
  "endpoints": {
    "json": {
      "search": {
        "url": "/books?search={query}",
        "path": "results",
        "title": "title",
        "url_": "id",
        "author": "authors[].name",
        "thumb": "formats.image/jpeg",
        "description": "summaries[]",
        "limit": 20
      },
      "details": {
        "url": "/books?ids={mangaId}",
        "path": "results",
        "title": "title",
        "author": "authors[].name",
        "thumbnail": "formats.image/jpeg",
        "description": "summaries[]",
        "genres": "subjects[]"
      }
    }
  },
  "readable": true,
  "readableCheckedAt": "2026-09-30T07:19:24.435Z"
}

What the mappings mean

  • path — where in the response the result array lives. "results" means response.results.
  • title, author, thumb, description — dot paths into each result object. Array steps use [] and [n], so authors[].name takes the name from every author.
  • url_ — the identifier passed back into details. The trailing underscore avoids colliding with the page URL.
  • {query} and {mangaId} — substituted at request time.
  • limit — how many results to request.

thumb and thumbnail are both accepted; thumbnail is used on the details endpoint.

#Madara source

Also a real definition, from the shipped registry. There are no endpoints: the engine supplies them. 

{
  "id": "kora-manga-s2read",
  "name": "S2Read",
  "lang": "en",
  "version": 1,
  "nsfw": false,
  "piracy": true,
  "kind": "manga",
  "theme": "madara",
  "baseUrl": "https://s2read.com",
  "icon": "https://raw.githubusercontent.com/CHAOTIC-RAY/Kora-Sources/main/icons/s2read.png",
  "gen2": {
    "packageName": "eu.kanade.tachiyomi.extension.en.s2read",
    "versionName": "1.4.7",
    "versionCode": "17",
    "homeUrl": "https://s2read.com"
  },
  "headers": {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/122.0.0.0 Safari/537.36"
  },
  "madara": {
    "mangaSubString": "manga",
    "popularOrderBy": "views",
    "latestOrderBy": "update"
  },
  "readable": true,
  "readableCheckedAt": "2026-09-30T07:19:40.806Z"
}

headers is worth setting for sites that reject requests without a browser user agent. madara holds overrides for sites that deviate from the default — path fragments and sort keys.

gen2 is optional. Set it to record which upstream Tachiyomi extension a port came from, so the source can be traced when the upstream site changes.

#Field reference

Source definition fields
FieldTypePurpose
idstringUnique identifier. Must be a string — a 64-bit Tachiyomi id loses precision as a JSON number and collides with other sources.
namestringShown on the chip and in the hub.
langstringLanguage code, e.g. "en".
versionnumberBump when your selectors break. Cached pages are re-fetched when it changes.
baseUrlstringSite origin, no trailing slash.
iconstringSquare PNG. See Icons.
categorystringsource, integration, tool or theme.
kindstringmanga, book or mixed. Decides which reader opens a result.
themestring"madara" to use the shared Madara engine.
apistring"json" for a JSON-API source.
endpointsobjectEndpoint mappings. Required unless theme supplies them.
piracybooleanGates the source behind a per-source opt-in. See flags.
nsfwbooleanSame gate, labelled Adult.
clientstring"cloudflare" to route through the Worker proxy.
headersobjectExtra request headers.
websitestringThe site's own home page.
descriptionstringOne line, shown in the hub.
gen2objectUpstream extension coordinates, for traceability.
readablebooleanLast verified readability verdict. See the gate.
readableNotestringWhy it failed, when it has.

#piracy and nsfw

These are policy fields, and they are the only two that change what a user sees before they install anything.

Gating behaviour
DefinitionWhat the user sees
Neither flag set Visible in the hub, no prompt.
"piracy": true Hidden until enabled for that source. Card is amber, labelled Shadow library.
"nsfw": true Hidden until enabled for that source. Card is amber, labelled Adult.
  • Either flag is enough to gate. The user opts in per source, and the choice is remembered on the device.
  • Only source plugins are gated. Themes, integrations and tools are never hidden by these flags.
  • Be accurate. A site that is not a shadow library should not set piracy, and using the flag to make a source look gated does not help anyone.

#Icons

Commit a square PNG to the registry repo and point icon at its raw URL: 

"icon": "https://raw.githubusercontent.com/CHAOTIC-RAY/Kora-Sources/main/icons/s2read.png"

A missing icon produces a warning at build time and a generic monogram in the app, which makes a grid of sources hard to scan — several indistinguishable cards. Ship an icon.

#Testing a source

A definition that lists titles is not yet a source that works. Run these from the registry repository, which holds the definitions and the tooling: 

npm run build:index      # generate index.json
npm run verify:index    # every URL in the index resolves
npm run verify:readable # fetch real page images from a live site
npm run verify          # build with the strict gate on

verify:readable drives the same parser the app reads with, so a source that passes here is a source the app can open. It needs a checkout of the app repository alongside the registry — set KORA_REPO_DIR if it is not a sibling directory.

To check one source against a live site, rather than the whole registry:

node scripts/verify-readable.mjs s2read

Verdicts are recorded in readable-history.json, eight entries per source, so a site that works and later stops is visible as a change rather than being silently overwritten.

#The readability gate

A source can browse correctly and still be unusable, because the page images are the part that matters and they are fetched last. One source in the shipped registry lists 661 chapters, passes every structural check, and returns HTTP 404 for every panel — a black rectangle with no error.

npm run build:index warns about any source marked "readable": false, and about any source whose readability was never verified. To make either fatal in CI: 

KORA_STRICT_READABLE=1 npm run verify

On Windows, set the variable in the environment rather than as a command prefix — the inline form is not valid there. npm run verify already passes the equivalent --strict flag, which is what the flag exists for.

A source that cannot serve real page images should not be published as working. Either fix it or record "readable": false with a readableNote saying why, so the failure is visible in the registry instead of at read time.

Recording a failure looks like this, from the shipped registry:

"readable": false,
"readableCheckedAt": "2026-09-30T07:19:29.097Z",
"readableNote": "panels: panel not served for 3 chapter(s)"

#Publishing a registry

A registry is a repository containing an index.json and the definitions it points at. Kora fetches the index at runtime, so the raw URL is all that has to be shared.

The index shape Kora expects:

{
  "extensionList": {
    "extensions": [
      {
        "name": "S2Read",
        "packageName": "eu.kanade.tachiyomi.extension.en.s2read",
        "extensionLib": "kora-1",
        "versionCode": "17",
        "versionName": "1.4.7",
        "resources": {
          "apkUrl": "https://raw.githubusercontent.com/OWNER/REPO/main/sources/manga/s2read.json",
          "iconUrl": "https://raw.githubusercontent.com/OWNER/REPO/main/icons/s2read.png"
        },
        "sources": [
          { "id": "kora-manga-s2read", "name": "S2Read", "language": "en", "category": "source" }
        ]
      }
    ]
  }
}

Extensions are read from extensionList.extensions, and each entry's resources.apkUrl is fetched to load the definition. build-index.mjs generates this file from the definitions in sources/, so in practice you write definitions and let the script produce the index.

Adding your registry to Kora

  1. Open Discover to reach the plugin hub.
  2. Enter the raw URL of your index.json in the repository field and add it.
  3. Your sources appear alongside the shipped ones. Remove the repository later from the same place.

Third-party registries load without a prompt

Adding a registry is a plain URL submission. There is no confirmation dialog and no allow-list of first-party registries, and a registry's definitions are read the same way as the shipped one. Read a registry before adding it, and prefer hosting your own.
